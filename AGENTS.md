## Invariants (each has a test)

1. **Decisions never see the truth.** Planners, the policy, training, model selection and the
   planning API read the belief only (`Env.observe`, `Env.view`). Only `sar.sim`, `sar.runner`,
   `sar.evaluation` and `sar.api.debrief` (after an approval) may call `truth_state()`.
   `tests/test_isolation.py` checks the code and runs every planner against a poisoned truth.
   C++: `test_env.cpp` "decisions see only the belief".
2. **The shield has the last word.** Every action passes the C++ shield (grid, no-fly zones,
   battery to return with the reserve). Rule violations after the shield must be 0 in every
   evaluation; the masks the policy sees are the shield's.
3. **Models propose, people approve.** Nothing is uploaded to a vehicle without an approval;
   approvals and uploads are append-only (no update or delete route).
4. **Interfaces are checked against independent implementations**: MAVLink against pymavlink,
   DIS against Open-DIS. Never test the codec only against itself.
5. **Settings live in `config/`**: lake, objects, simulation, training, evaluation.
   `config/sensor_calibration.yaml` is generated by `sar calibrate`; do not edit it by hand.
6. **Training never uses dev or held-out scenarios**: it draws from `config/sim.yaml:
   training_distribution`; validation uses generator seeds from 900000, imitation from 500000.
7. **Reports are generated** and reproducible; CI re-runs the dev evaluation and diffs it.

## The held-out rule

`heldout/blind-1` was written by someone who read only `heldout/WRITING_SCENARIOS.md`. It runs
once (`sar heldout --set heldout/blind-1`); the first run in `reports/heldout/blind-1/` is never
rewritten, and `tests/test_heldout.py` pins the set and the run by sha256.

- Never change planners, the policy, the shield or configuration to do better on it.
- If you study its failures, write `regression` to `heldout/blind-1/STATUS`, move it to
  `scenarios/`, and have someone who has not seen the code write a new set from the guide.
